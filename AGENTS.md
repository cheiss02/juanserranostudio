# Repository Notes

- This is a small set of self-contained static pages — no framework, no bundler, no build step.
  - `index.html` is the homepage: a Fibonacci-sphere sports photo archive (splash, intro film, drag-to-rotate sphere, flat grid, lightbox). Its CSS is `style.css`; its behavior is `script.js` (sphere/grid/lightbox-specific, not shared). It keeps its own full-screen hamburger menu — that's deliberate, don't change it to the horizontal nav below without being asked.
  - Every other page (`portfolio.html`, `sport.html`, `quinceanera.html`, `wedding.html`, `photobooth.html`, `portraits.html`, `services.html`, `about.html`, `contact.html`, `privacy.html`, `terms.html`) shares `style.css` and `nav.js` for an always-visible horizontal header nav (`.site-nav`: Portfolio/Services/About/Contact + EN/ES), no hamburger. Each page defines its own `UI` translation object inline and calls `initSiteChrome(UI)`.
  - The 5 gallery pages (`sport.html`, `wedding.html`, `quinceanera.html`, `photobooth.html`, `portraits.html`) also call `nav.js`'s `initGallery({folder, photos})`, which builds the thumbnail grid and an in-page lightbox (click to view full-size with title/place/description; closes via the Close button or Escape — never opens the raw file in a new tab).
- Bilingual (EN/ES) throughout via `data-i18n` / `data-i18n-html` attributes + a `UI` dictionary per page (see `script.js`'s `applyLang()` for the homepage, `nav.js`'s `initSiteChrome()`/`initGallery()` for the rest). When adding copy, add both languages together.
- Portfolio categories, in the required order, are: Wedding, Quinceañera, Photo Booth, Portraits, Sport. Keep `services.html`'s service rows and `portfolio.html`'s category tiles in that same order.
- Media lives in `assets/`: `assets/intro.mp4` (currently absent — gracefully falls back to the gradient), `assets/avatar.jpeg` (Juan's portrait, also used on `about.html`), `assets/logo-white.png` (original color logo, used for favicons) + `assets/logo-mono.png` (white silhouette, used in header/splash) + `assets/logo-color.png` (unprocessed backup), `assets/photos/01.jpg`–`13.jpg` (13 unique real sports photos — the homepage sphere cycles them into 21 slots; `sport.html` shows all 13 once each), `assets/wedding/01-04.jpg`, `assets/quinceanera/01-07.jpg`, `assets/portraits/01-06.jpg`, `assets/services/photobooth.jpg` (stock example photo, credited on-page — no real photo booth photo exists yet). All real photos are the client's own; downscaled to ~2000px/85% quality on import, never committed at original multi-MB size. More real photos are expected over time — ask before assuming a category's photo count is final.
- Contact info (email, phone, WhatsApp) is sourced from the live reference site at juanserranostudio.vercel.app — info@juanserranostudio.com / help@juanserranostudio.com / (562) 396-3548. Don't invent different contact details.
- The quote form on `contact.html` has no backend — it composes a `mailto:` link client-side. Don't silently wire it to a real form service without the user's say-so.
- `privacy.html` / `terms.html` are generic, good-faith legal pages, explicitly labeled as not legal advice — don't present them as attorney-reviewed, and flag to the user that a real review is still worth getting before relying on them commercially.
- GitHub Pages is driven by `.github/workflows/deploy.yml`, which stages only the actual site files (`*.html`, `style.css`, `script.js`, `nav.js`, `CNAME`, `assets/`) into a clean `_site/` directory before publishing — it does **not** publish the whole repo root. If you add a new top-level file type the site needs (e.g. another shared `.js`/`.css` file), add it to that staging step too, or it won't deploy; new `.html` files are picked up automatically via glob. `.claude/`, `AGENTS.md`, `CLAUDE.md`, `README.md`, and `.github/` are intentionally excluded from the published site. Open any `.html` file in a browser, or serve the folder with a static file server, to preview locally — there is nothing to build.
- `CNAME` at the repo root configures the `juanserranostudio.com` custom domain for GitHub Pages; keep it unless the domain changes. Nothing has been pushed to a remote/deployed live as of this writing — confirm with the user before pushing to `main` or changing DNS/Pages settings.
- Do not add server-only secrets to client code — these are static pages with no backend.
- `.claude/skills/` holds installed Claude Code skills (impeccable, transitions-dev/-polish/-ui-generation, gsap-*, make-interfaces-feel-better, motionsites-web-builder) for UI/motion polish work on this project. `.claude/settings.local.json` is personal-local and gitignored — don't commit it.
