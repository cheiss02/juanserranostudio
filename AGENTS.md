# Repository Notes

- This is a small set of self-contained static pages — no framework, no bundler, no build step.
  - `index.html` is the homepage: a Fibonacci-sphere sports photo archive (splash, intro film, drag-to-rotate sphere, flat grid, lightbox). Its CSS is `style.css`; its behavior is `script.js` (sphere/grid/lightbox-specific, not shared).
  - `portfolio.html` (Sport/Quinceañera/Wedding/Photo Booth category hub), `sport.html`, `quinceanera.html`, `wedding.html`, `photobooth.html` (simple per-category gallery pages), `services.html`, `about.html`, `contact.html` share `style.css` for look, and `nav.js` for the header/hamburger menu, EN/ES language toggle, and custom cursor. Each page defines its own `UI` translation object inline and calls `initSiteChrome(UI)`.
- Bilingual (EN/ES) throughout via `data-i18n` / `data-i18n-html` attributes + a `UI` dictionary per page (see `script.js`'s `applyLang()` for the homepage, `nav.js`'s `initSiteChrome()` for the rest). When adding copy, add both languages together.
- Media lives in `assets/`: `assets/intro.mp4` (currently absent — gracefully falls back), `assets/avatar.jpeg`, `assets/logo-white.png` + `assets/logo-mono.png` (white silhouette, used in header/splash) + `assets/logo-color.png` (unprocessed original backup), `assets/photos/01.jpg`–`21.jpg` (homepage sphere + sport.html gallery), `assets/quinceanera/`, `assets/wedding/`, `assets/services/photobooth.jpg`. Several of these are temporary placeholders pending final client assets — check with the user before assuming any photo/video is final.
- Contact info (email, phone, WhatsApp) is sourced from the live reference site at juanserranostudio.vercel.app — info@juanserranostudio.com / help@juanserranostudio.com / (562) 396-3548. Don't invent different contact details.
- The quote form on `contact.html` has no backend — it composes a `mailto:` link client-side. Don't silently wire it to a real form service without the user's say-so.
- GitHub Pages is driven by `.github/workflows/deploy.yml`, which stages only the actual site files (`*.html`, `style.css`, `script.js`, `nav.js`, `CNAME`, `assets/`) into a clean `_site/` directory before publishing — it does **not** publish the whole repo root. If you add a new top-level file type the site needs (e.g. another shared `.js`/`.css` file), add it to that staging step too, or it won't deploy. `.claude/`, `AGENTS.md`, `CLAUDE.md`, `README.md`, and `.github/` are intentionally excluded from the published site. Open any `.html` file in a browser, or serve the folder with a static file server, to preview locally — there is nothing to build.
- `CNAME` at the repo root configures the `juanserranostudio.com` custom domain for GitHub Pages; keep it unless the domain changes.
- Do not add server-only secrets to client code — these are static pages with no backend.
- `.claude/skills/` holds installed Claude Code skills (impeccable, transitions-dev/-polish/-ui-generation, gsap-*, make-interfaces-feel-better) for UI/motion polish work on this project. `.claude/settings.local.json` is personal-local and gitignored — don't commit it.
